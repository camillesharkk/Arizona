# 新增 Notary Prep 州站

## 1. 目标与完成标准

新州必须具备现有成熟州的完整适用功能，而不只是可以访问的首页。

以当前生产 AZ 为界面和功能基准，吸收 CA、HI 已验证的通用能力。历史需求和历史交付报告只能作为线索，必须检查当前代码与生产行为。

只有内容、学习流程、账号权益、SEO 和生产复查达到要求后，才报告完成。

禁止以下替代交付：

- 用 Coming soon、空题库或说明文字代替功能。
- 只补按钮，不接入真实流程。
- 强制新州 isPro=false。
- 通过删掉旧州功能实现一致。
- 只凭构建通过就宣称浏览器流程通过。
- 把部署 READY 当作正式站已完整验收。
- 将可修复的问题列为“后续优化”后提前结束。

## 2. 确认生产基准与工作范围

开始前检查：

- 正式域名绑定的应用、仓库、生产分支和部署方式。
- 当前生产版本与工作区差异。
- 州注册表、路由、内容目录、商品及权益模型。
- 目标州已有页面、占位入口和历史公开地址。
- 当前任务是否同时存在其他未提交改动。

保留无关改动，不覆盖、不回滚、不误提交。

优先沿用既有公开 URL。不得为了新州接入迁移域名或重构整个网站。

新增内容和功能按目标州实施；共享组件修改需要回归现有州。

## 3. 功能对照与共享组件

逐页建立：页面｜基准州实际功能｜目标州实现｜共享组件路径｜差异依据｜验收结果。

至少覆盖首页、Practice、Questions、作答与成绩、Study Cards、Study Guide、Wrong Answers、Daily Study、Resources、考试指南、及格说明、法规、申请流程、Pricing、Dashboard、账号、导航、登录回跳，以及已经存在的 AI Tutor。

同类页面使用同一个实际主组件。路由负责州解析和元信息，州配置负责内容和考试规则。

功能对齐不要求官方考试规则一致。差异必须来自真实业务规则。

### 3.1 Study Guide 与 AZ 完全对齐的强制验收

每个迁移州的 Study Guide 必须逐项达到实施时生产 AZ 的页面结构、内容完整度和交互能力，并复用 AZ 的同一个实际主组件。章节按本州专题组织，法规、案例、来源、考试参数和全部学习链接使用本州配置。

以下字段全部必填，并逐项记录 AZ 基准、目标州实现、组件路径和实际浏览器结果。

- 页面标题、导读、官方手册或资源、法规和考试指南入口。
- 免费 Quick 10、按本州设置的完整练习、Study Cards 和 Wrong Answers 入口。
- 可跳转的 Chapters 目录和覆盖全部本州学习专题的完整章节正文。
- 每章摘要、多段规则与适用边界、完整 worked example、Key facts、本州官方依据及核验日期。
- 每章 Mark chapter read / Marked read，可标记和取消。
- Exam checklist，正确显示本州已读数量、章节总数、下一章和全部已读状态。
- 每章 Practice This Topic、Study this topic、Review wrong answers，URL 与专题 ID 必须匹配本州真实题目、知识卡和错题筛选。
- 按实际免费专题显示 Pro-only 提示和免费替代练习，并保留页面末尾的 Pro 入口。
- 桌面和移动端的完整布局、目录、按钮与长正文均可正常使用。

验收须实际执行匿名和登录账号的标记、取消、刷新持久化与跨州切换，验证用户和州隔离、正确 checklist、专题链接和 AZ 历史阅读记录兼容。目标州阅读进度必须显式传州代码，AZ 已有存储键与章节 ID 保持兼容。

只有专题链接、简介、知识卡跳转或可访问路由的页面均未达到 Study Guide 交付标准。视觉截图、类型检查、构建和部署 READY 分别记录，浏览器操作结果单独记录。任何必填项缺失时，继续补齐并复验后再宣布迁移完成。

## 4. 官方资料与考试配置

使用州政府、现行法规、官方手册和指定考试机构为主要依据。搜索摘要和竞品不能代替原文。

官方未公开的字段保持未知，不复制其他州参数。没有足够依据复刻正式考试时，实现标明为本站设置的 Comprehensive Practice，不把练习成绩写成官方结果。

## 5. 题库、知识卡与文章

有效题量至少为 max(203, 实施开始时 AZ 已发布、有效、去重题量)。独立知识卡至少 50 张，并覆盖核心专题。AZ 目录里的 204 张包含大量由题目直接转换的卡片，那些转换卡可以另计，但不能当作独立知识卡的对标数量，也不能对用户说成独立知识点数量。每州另写 10 篇独立原创英文文章。基础练习页和考试指南不能拿来凑文章数。

题目必须是原创英文情境，包含正确答案解释、每个错误选项的具体原因、本州官方依据和核验日期。不能把其他州题目换州名，也不能用只改姓名、金额或日期的模板凑数。

无法核实的题保留草稿，不发布。

## 6. 全站 60 天 VIP 与免费额度

VIP 已经是账号级权益时，不要为新州再做一次加时迁移，也不要新建州商品。来源州只用于统计和回跳。

免费题、Quick 10、匿名完整练习和登录免费额度沿用实施时的真实口径。新州不要整库免费，也不要整库收费。

学习记录按用户和州隔离。VIP 按账号共享。

## 7. 验收与发布

类型检查、生产构建和题库检查通过后，还要在浏览器走通匿名、登录免费、有效 VIP 和过期 VIP。跨州后第一次单击完整练习 Start 必须进入当前州考试。

只有内容和功能都达到上线条件，才把该州标成 Available，并写入公开 sitemap。

外部条件没满足时，完成可完成的代码和受保护预览，列出阻塞，不把该州报告为已上线。

## 8. 本次接入留下的通用教训

这些是工程事实，不是某个州的法律规则：

- 生产域名是 arizonanotaryprep.com，Vercel 项目 sharkkk/arizona，推送 main 才会发布生产。
- 已上线州以 `lib/states.ts` 里 `status: "available"` 为准，不按历史报告。
- CA 与 HI 的页面是同一套组件加本州配置。新州应走同一套，而不是再复制一套 Practice。
- `pathState()` 在共享页和 Coming soon 之外会回落到 AZ。新州路径必须先被识别，否则页头、场次和权限会用成亚利桑那。
- 完整练习的第一次点击依赖当前州的 `authReady`。切换州后必须丢掉上一州的请求结果，并在权限未返回时保留这次点击。
- 场次、匿名额度和 localStorage 键要带州代码。AZ、CA、HI 已有键不能改名，否则旧记录会丢。
- 官方考试题量、时长和及格规则未写明时保持空值。本站练习题量要在按钮和说明里写明是本站设置。
- 不计分题的身份存在该场次的 `unscoredIds` 里，刷新不能重抽。交卷前不标出哪些题不计分。
- 路易斯安那备考服务是否必须向州务卿登记，是该州的发布条件，不要写成所有州的规则。
- `.cursor/` 被 gitignore。要把本 Skill 纳入版本库时，需要对该文件强制加入。
